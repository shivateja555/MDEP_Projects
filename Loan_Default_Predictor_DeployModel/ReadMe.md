# 🏦 Loan Default Prediction

A full ML lifecycle project for predicting loan defaults using XGBoost, with SMOTE for class imbalance, MLflow experiment tracking, SHAP explanations, data drift monitoring (PSI/CSI/KS), and Flask API deployment via Docker.

---

## 📁 Project Structure

```
project/
├── app.py              # Flask REST API for serving predictions
├── model.py            # ML pipeline: preprocessing, training, MLflow tracking
├── drift.py            # Data drift: PSI, CSI, KS statistics
├── explain.py          # XAI: SHAP summary, beeswarm & waterfall plots
├── requirements.txt    # Python dependencies
├── Dockerfile          # Container definition
├── EDA_Loan_Default.ipynb  # Exploratory Data Analysis notebook
├── mlruns/             # MLflow experiment artifacts
├── models/             # Saved model files
├── artifacts/          # Plots (SHAP, confusion matrix, drift)
└── data/
    ├── Dataset.csv
    └── Data_Dictionary.csv
```

## 🚀 Quick Start

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Run EDA
```bash
jupyter notebook EDA_Loan_Default.ipynb
```

### 3. Train models (runs 2 MLflow experiments)
```bash
python model.py
```

### 4. View MLflow UI
```bash
mlflow ui
# Open http://localhost:5000
```

### 5. Start the prediction API
```bash
python app.py
# API runs on http://localhost:5000
```

## 📊 MLflow Experiments

Two experiments are run with different hyperparameters:

| Parameter | Experiment 1 (Conservative) | Experiment 2 (Deeper) |
|-----------|-----------------------------|-----------------------|
| n_estimators | 200 | 500 |
| max_depth | 4 | 6 |
| learning_rate | 0.05 | 0.01 |
| subsample | 0.8 | 0.7 |
| reg_alpha | 0.1 | 0.5 |

**Tracked metrics:** ROC-AUC, F1, Precision, Recall, Avg Precision, PSI, KS

---

## 🧠 ML Design Decisions

### Handling Class Imbalance
- **SMOTE** (Synthetic Minority Oversampling Technique) in training pipeline
- `scale_pos_weight` in XGBoost (≈11, ratio of negatives to positives)
- Evaluation with ROC-AUC and Average Precision (not accuracy)

### Missing Values
- Numeric: **Median imputation** (robust to outliers)
- Categorical: **Mode imputation**
- High-missing features (>60%): retained as-is; missingness itself can be informative

### Outliers
- `RobustScaler` used (IQR-based, not sensitive to outliers)
- No hard removal — tree models handle outliers naturally

### Feature Engineering (10 derived features)
- `Age_Years`, `Employed_Years` — human-readable from days
- `Debt_Income_Ratio`, `Annuity_Income_Ratio` — affordability signals
- `Score_Mean`, `Score_Std` — aggregate credit score signals
- `Phone_Reachability` — contact availability indicator

## 📉 Data Drift Monitoring

The `drift.py` module computes:
- **PSI (Population Stability Index):** < 0.1 stable, 0.1-0.2 moderate, > 0.2 high drift
- **CSI (Characteristic Stability Index):** per-feature PSI
- **KS Test:** non-parametric distribution comparison (p < 0.05 = drift detected)

All metrics logged to MLflow per experiment.

---

## 🔍 XAI — SHAP Explanations

Generated by `explain.py`:
- **Bar plot:** global feature importance (mean |SHAP|)
- **Beeswarm plot:** direction + magnitude of feature impact
- **Waterfall plot:** single prediction decomposition for highest-risk case
- **CSV:** ranked feature importance table

---

## 🎯 Evaluation Strategy

Since the dataset is heavily imbalanced (~9% default rate), we use:
- **Primary metric:** ROC-AUC (threshold-independent)
- **Secondary:** Average Precision (handles imbalance better than AUC)
- **Operational:** F1, Precision, Recall (business-relevant tradeoffs)
